# Plan 1.2: NextAuth Authentication with @rvce.edu.in Domain Enforcement

## Objective
Implement institutional authentication via NextAuth.js enforcing strict `@rvce.edu.in` domain validation, attach role-based permissions (`STUDENT`, `CLUB_OWNER`, `ADMIN`) to the session, and create the client-side authentication UI (Sign In modal with domain notice, user profile menu, and session provider).

  <name>Implement NextAuth Route Handler and Domain Guard</name>
  <files>
    src/lib/auth.ts

    src/types/next-auth.d.ts

  <action>
    Configure NextAuth with Google OAuth provider, domain verification, and role session propagation.

    Steps:
    1. Install `next-auth` and `@next-auth/prisma-adapter`.
    2. Create `src/types/next-auth.d.ts` augmenting `Session` and `User` interfaces with `id: string`, `role: Role`, and `clubId?: string | null`.
    3. Create `src/lib/auth.ts` with `authOptions`:
       - Configure `PrismaAdapter(prisma)`.
       - Add `GoogleProvider` with `authorization: { params: { hd: "rvce.edu.in" } }`.
       - Add a development-only `CredentialsProvider` fallback (enabled only when `NODE_ENV === "development"` and `ENABLE_DEV_LOGIN === "true"`) allowing testing as mock student, club owner, or admin with `@rvce.edu.in` emails without requiring active Google API credentials.
       - Implement `signIn` callback:
         ```ts
         if (!user.email || !user.email.endsWith("@rvce.edu.in")) {
           return false; // Reject sign in for non-RVCE accounts
         }
         return true;
         ```
       - Implement `session` callback: fetch and attach user's `id`, `role`, and `clubId` to `session.user`.
    4. Implement `src/app/api/auth/[...nextauth]/route.ts` exporting `GET` and `POST` handlers.
    5. Document required environment variables in `.env.example` (`NEXTAUTH_URL`, `NEXTAUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DATABASE_URL`).

    AVOID: Allowing non-RVCE emails through if Google OAuth returns an account from a different domain.
    USE: Explicit server-side validation in `signIn` callback in addition to the `hd` query parameter.
  </action>
  <verify>
    npm run build
  </verify>
  <done>
    NextAuth route compiles without TypeScript errors; non-RVCE email test cases are rejected by domain verification logic in `authOptions.callbacks.signIn`.
  </done>
</task>
