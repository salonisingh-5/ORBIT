# Plan 4.2 Summary: Main Admin Dashboard, Club Provisioning, and Opportunity Moderation

## Objective Accomplished
Constructed the central Main Admin Dashboard at `/admin`: role-based authorization restricting access strictly to `ADMIN` users, opportunity moderation queue (review, approve, reject, edit, delete across all clubs), club directory management (create/edit clubs), and user role provisioning (assigning `STUDENT`, `CLUB_OWNER`, `ADMIN` and linking club affiliations).

## Components Created & Modified

1. **Admin Service & Data Layer (`src/lib/admin-portal.ts`)**:
   - `getAdminMetrics()`: Total users, total clubs, total opportunities, approved count, pending count, and rejected count.
   - `getAllClubs()`, `createClub()`, `updateClub()`: Manages official campus club directory with dual Prisma database and in-memory persistence.
   - `getAllUsers()`, `updateUserRoleAndClub()`: User management supporting promotion/demotion between `STUDENT`, `CLUB_OWNER`, `ADMIN` and club assignment.
   - `getAdminOpportunities()`, `moderateOpportunity()`, `updateOpportunityAsAdmin()`, `deleteOpportunityAsAdmin()`: Full moderation capability across all clubs.

2. **REST API Endpoints (`src/app/api/admin/*`)**:
   - `GET /api/admin/clubs`: Rejects non-admins with 403 Forbidden. Returns all registered clubs.
   - `POST /api/admin/clubs`: Registers a new club with input validation.
   - `PUT /api/admin/clubs/[id]`: Next.js 15 typed route handler to update club metadata.
   - `GET /api/admin/users`: Rejects non-admins with 403 Forbidden. Returns user directory.
   - `PATCH /api/admin/users`: Updates user role (`STUDENT`, `CLUB_OWNER`, `ADMIN`) and club linkage.
   - `GET /api/admin/opportunities`: Fetches opportunities with optional status filter (`ALL`, `SUBMITTED`, `APPROVED`, `REJECTED`, `DRAFT`) and metrics.
   - `PATCH /api/admin/opportunities/[id]`: Moderates opportunity status (Approve, Reject).
   - `PUT /api/admin/opportunities/[id]`: Updates opportunity details.
   - `DELETE /api/admin/opportunities/[id]`: Removes opportunity from the catalog.

3. **Front-End Administration Console (`src/components/admin/*`, `src/app/admin/page.tsx`)**:
   - `src/components/admin/admin-auth-guard.tsx`: Displays HTTP 403 Access Denied banner for non-admins (`STUDENT`, `CLUB_OWNER`) and sign-in modal for unauthenticated visitors.
   - `src/components/admin/club-modal.tsx`: Modal for registering and editing campus clubs with slug auto-generation.
   - `src/components/admin/admin-dashboard-view.tsx`: 3-tab editorial console:
     - **Tab 1: Opportunity Moderation**: Status badges, pending review counter, one-click Approve/Reject, and permanent deletion with confirmation.
     - **Tab 2: Club Registry**: Directory cards, owner & event counts, website links with `rel="noopener noreferrer"`, and edit actions.
     - **Tab 3: User Roles & Access**: Searchable user table, role selector (`STUDENT`, `CLUB_OWNER`, `ADMIN`), club assignment dropdown, and instant update actions.
   - `src/app/admin/page.tsx`: Server component enforcing `ADMIN` role and loading all datasets concurrently.

4. **Master Test Suite Integration**:
   - `test/admin-portal.test.mjs`: Added 6 comprehensive test cases covering non-admin 403 rejection, club registration/updates, club input validation, user role provisioning & demotion, opportunity moderation, and opportunity deletion.
   - Integrated into `test/run-all.mjs`.
