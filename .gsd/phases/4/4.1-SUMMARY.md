# Plan 4.1 Summary: Club Owner Portal and Scoped Opportunity Management

## Objective Accomplished
Constructed the dedicated Club Owner portal at `/club-dashboard`: role-based access control, scoped opportunity creation, editing, status management, and deletion strictly limited to the authenticated club's events.

## Components Created & Modified

1. **Scoped Data Access Layer (`src/lib/club-portal.ts`)**:
   - `getClubOpportunities(clubIdentifier, userRole)`: Queries opportunities belonging strictly to the assigned club, with full bypass for `ADMIN`.
   - `createClubOpportunity(data, user)`: Validates ownership role (`CLUB_OWNER` or `ADMIN`) and sets `clubId = resolvedClub.id`.
   - `updateClubOpportunity(id, data, user)`: Validates ownership before modifying opportunity data; rejects cross-club updates with 403 Forbidden.
   - `deleteClubOpportunity(id, user)`: Validates ownership before deletion; prevents cross-club deletion with 403 Forbidden.
   - `resolveUserClub(user)`: Resolves club mapping and provides clean in-memory fallback for local development.

2. **Backend API Endpoints**:
   - `src/app/api/club/opportunities/route.ts`:
     - `GET`: Rejects unauthenticated requests with 401 and student accounts with 403 Forbidden. Returns club profile and opportunities.
     - `POST`: Validates title, category, description, officialUrl, and deadline. Rejects students with 403. Creates and returns opportunity.
   - `src/app/api/club/opportunities/[id]/route.ts`:
     - `PUT`: Next.js 15 typed route handler (`Promise<{ id: string }>`). Verifies club ownership and updates opportunity fields.
     - `DELETE`: Verifies club ownership and removes opportunity.

3. **Front-End UI & Dashboard (`src/components/club/*`, `src/app/club-dashboard/page.tsx`)**:
   - `src/components/club/opportunity-form-modal.tsx`: Modal supporting both Create and Edit flows, with full validation, category selection, and loading states.
   - `src/components/club/club-dashboard-view.tsx`: Club dashboard with metric cards (Total, Published, Approaching Deadlines, Drafts), search, status filters, external links with `rel="noopener noreferrer"`, and management actions.
   - `src/components/club/club-auth-cta.tsx`: Handles both unauthenticated one-click sign-in and HTTP 403 Access Restricted views for students.
   - `src/app/club-dashboard/page.tsx`: Server component enforcing role checks (`CLUB_OWNER` | `ADMIN`), fetching scoped opportunities, and rendering the view.

4. **Master Test Suite Integration**:
   - `test/club-portal.test.mjs`: Added 7 test cases covering student 403 rejection on access & creation, club owner scoped creation/editing/deletion, cross-club tamper prevention, input validation, and admin privilege.
   - `test/run-all.mjs`: Integrated suite into master test runner.

## Verification Results

- **`npm test`**: 7 test suites, 36/36 tests passing cleanly.
- **`npm run build`**: 11 routes compiled cleanly with 0 TypeScript or lint errors.
- **Security & Authorization**:
  - Students cannot create, edit, or delete opportunities (enforced server-side with 403 Forbidden).
  - Cross-club tampering is prevented server-side.
  - Form validation enforces minimum lengths, valid URLs, and valid deadlines.
  - External links use `rel="noopener noreferrer"`.
