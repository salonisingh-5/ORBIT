# Plan 4.1: Club Owner Portal and Scoped Opportunity Management

## Objective
Construct the dedicated Club Owner portal at `/club-dashboard`: role-based access control, scoped opportunity creation, editing, status toggling (publish/cancel), and deletion strictly limited to the authenticated club's events.

## Context
Load these files for context:
- .gsd/SPEC.md
- .gsd/REQUIREMENTS.md
- src/lib/auth.ts
- src/lib/session.ts
- src/lib/opportunities.ts

## Tasks

<task type="auto">
  <name>Build Scoped Club Opportunity Data Layer and REST API</name>
  <files>
    src/lib/club-portal.ts
    src/app/api/club/opportunities/route.ts
    src/app/api/club/opportunities/[id]/route.ts
  </files>
  <action>
    Construct the scoped data layer and backend endpoints enforcing strict ownership and role verification.

    Steps:
    1. Create `src/lib/club-portal.ts`:
       - `getClubOpportunities(clubId)`: queries opportunities belonging strictly to `clubId`.
       - `createClubOpportunity(data, user)`: validates input and creates opportunity with `clubId = user.clubId`.
       - `updateClubOpportunity(id, data, user)`: verifies ownership before updating.
       - `deleteClubOpportunity(id, user)`: verifies ownership before deleting.
       - Resilient in-memory fallback for local dev when PostgreSQL is offline.
    2. Create `src/app/api/club/opportunities/route.ts`:
       - `GET`: verifies session role (`CLUB_OWNER` or `ADMIN`), returns club opportunities.
       - `POST`: verifies session role, validates title, officialUrl, deadline, and creates opportunity.
    3. Create `src/app/api/club/opportunities/[id]/route.ts`:
       - `PUT`: updates opportunity details with ownership check.
       - `DELETE`: deletes opportunity with ownership check.
  </action>
  <verify>
    npm test
  </verify>
  <done>
    Club opportunity API endpoints registered and verified.
  </done>
</task>
